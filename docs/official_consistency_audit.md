# WoTE 官方一致性核对

核对基准：官方 [论文 arXiv:2504.01941v2](https://arxiv.org/html/2504.01941) 和
[官方仓库 main（298957c）](https://github.com/liyingyanUCAS/WoTE/tree/298957c)。
本地与该提交逐文件比较；本次检查的是 NAVSIM 实现，不包含 Bench2Drive。

## 主要配置

| 项目 | 公开实现及本地配置 |
| --- | --- |
| 输入 | 256×1024 图像、64 m×64 m LiDAR、ResNet34 图像及 LiDAR 主干 |
| 轨迹 | 256 个聚类锚点，4 秒、每 0.5 秒一个点 |
| 世界模型 | 2 层 Transformer encoder，默认递推 1 次；训练以锚点、推理以修正轨迹编码为输入 |
| 奖励 | 模仿、NC、DAC 和加权仿真奖励的系数依次为 0.1、0.5、0.5、1.0 |
| 损失 | 轨迹偏移系数 1.0；偏移模仿奖励系数 0.1；模仿及仿真奖励损失直接相加；当前/未来 BEV 系数 10.0/0.1 |
| 训练入口 | Navtrain、8 卡、每卡 batch 16、累积 1 次、30 轮；基础学习率 1e-4 |
| 优化器 | 官方默认 AdamW，weight decay 1e-4；3 轮 warmup，余弦调度周期使用配置中的 100 轮、最小学习率 1e-6 |

通用训练 YAML 的 batch 32、20 轮是通用默认值；WoTE 官方启动脚本覆盖为 16、30。
`num_plan_queries=32` 在当前实现中被 `num_keyval=64` 覆盖，实际使用 64；此行为与官方一致。
调度器使用统一的学习率列表；尽管优化器创建时对 image encoder 设置 0.1 倍学习率，
调度器初始化后未保留这一倍率。这也是官方代码现有行为。
配置中 `im_loss_weight` 和 `metric_loss_weight` 都是 1.0，但损失实现未读取这两个字段。

## 论文、官方代码和本地适配的区别

* 论文称使用 Adam；公开代码默认启用 AdamW 和上述 warmup/cosine 调度。两者无法同时严格满足；
  保留公开代码，以免改变官方权重对应的实现。
* 论文实验表描述 0→2→4 秒的两次未来预测，而公开代码默认 `num_fut_timestep=1`，
  即单次递推。该值影响奖励网络尺寸和检查点兼容性，保留公开代码。
* 论文称世界模型采用两层 transformer decoder；公开代码是两层 `TransformerEncoder`。
* 官方 GPU 配置为混合精度，当前 NPU 适配仅支持 FP32；本地锚点及轨迹标签显式转为
  float32。因此无法保证与 GPU 混合精度的数值结果完全相同。设备迁移、结果导出及保存功能
  也是本地扩展。评测默认保存额外模型结果，但评分和轨迹选择公式与上游相同。
* 官方训练和评测脚本硬编码作者机器路径。本地入口改为使用激活环境中的数据、地图和输出路径，
  明确使用当前仓库，训练完成后不再自动启动评测。GPU 仍使用官方的混合精度；设置
  `WOTE_ACCELERATOR=npu` 选择本地 NPU FP32 适配。训练使用 8 张可见设备；已有环境默认只
  暴露一张，启动前须按实际设备设置 `ASCEND_RT_VISIBLE_DEVICES`。
  评测入口使用 `WOTE_CHECKPOINT_PATH`，如果设置了 `WOTE_METRIC_CACHE_ROOT`，则使用其
  `navtest` 子目录作为缓存；否则沿用官方默认缓存位置。
* 历史 smoke 运行的 1 轮、小样本和小 batch 是链路测试配置，不能视作论文完整训练设置。

本地资源路径存在，但仅凭文件存在不能证明下载文件与官方发布文件逐字节相同，亦未核验完整
NAVTRAIN 传感器数据。此次没有启动全量训练或评测，也没有验证 8 卡、每卡 batch 16 的显存和吞吐。
